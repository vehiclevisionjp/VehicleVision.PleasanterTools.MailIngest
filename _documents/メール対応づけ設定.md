# メール対応づけ設定（設計案）

<!-- markdownlint-configure-file {"MD013": {"line_length": 120}} -->

## 1. 形式とサンプル

第 1 段階のレビュー用 JSON 例。**現行 CLI はまだ読み込めない。**
`schemaVersion` で将来の変更を識別し、未知の版・プロパティ・ソース ID 重複を起動時に拒否する。
取り込み元は「アカウント + 対象フォルダ / 条件 + 送り先」の 1 定義。
`sourceId` は接続先変更でも重複排除の名前空間を保つ不変 ID とし、別アカウントへ使い回さない。

ドメイン・ID・列・選択肢の値は説明用。`Status=100` を有効と保証しない。
`destinationId` は接続先を表す不変 ID。URL の表記変更で変えず、別環境へ転用しない。
siteId・sourceId・destinationId の変更は別の取り込み先 / 名前空間となるため、移行手順が必要。
POP3 例で省略した制限は上の IMAP 例と同じ既定候補を適用する。
IMAP に pop3 設定、POP3 に imap 設定が混在した場合も起動エラー。
接続保護は次の 3 モード。`tls` の値は大文字小文字も表のとおりとし、未知値は起動エラー。
MailKit の列挙値名をそのまま外部設定には使わない。

| `tls` | 意味 | POP3 / IMAP の既定ポート | MailKit への対応 |
| --- | --- | --- | --- |
| `None` | 平文。明示設定だけ | 110 / 143 | `SecureSocketOptions.None` |
| `StartTls` | STLS / STARTTLS で同じ接続を昇格 | 110 / 143 | `SecureSocketOptions.StartTls` |
| `Tls` | 暗黙 TLS。省略時の既定 | 995 / 993 | `SecureSocketOptions.SslOnConnect` |

`port` 省略時だけモード別の既定ポートを補い、明示時は 1〜65535 の整数を使う。
ポート番号からモードを推測しない。`Auto` / `StartTlsWhenAvailable` や平文への自動降格は許可しない。
`StartTls` の非対応・失敗、`Tls` の失敗時は認証せず停止する。
既定 `Tls` は暗号化忘れを避ける安全側の決定。
代替の `StartTls` 既定案は旧ポートを維持できるが昇格対応が必要なため、明示選択にとどめる。

`authentication.allowedMechanisms` は順序に依存しない許可リスト。
TLS 利用時の省略値は、POP3 が `PLAIN` / `LOGIN` / `USER/PASS`、
IMAP が `PLAIN` / `LOGIN` / `IMAP-LOGIN`。`LOGIN` は SASL、`IMAP-LOGIN` は IMAP コマンドを区別する。
非 SASL の `USER/PASS`・`APOP` は POP3 専用。プロトコル不一致・未知値は起動エラー。
APOP / CRAM-MD5 は既定無効で、必要なら `APOP` / `CRAM-MD5` を個別指定する。
その他の MailKit 対応 SASL は評価後に許可値を追加する案とし、未評価の値を自動許可しない。

`None` では許可リストの既定は空。非空のリストを明示しなければ起動エラーにする。
平文の USER/PASS・IMAP LOGIN・SASL PLAIN/LOGIN を許可する場合は、加えて
`allowInsecurePasswordAuthentication: true` が必要。既定は `false`。
APOP / CRAM-MD5 はこのフラグ不要だが、古い認証方式のリスクと本文の無保護は変わらない。
いずれも設定外の方式や非 SASL へのフォールバックを禁止する。

次は旧式 POP3 を利用するための **ソース設定の差替え断片**。完全な実行設定ではない。
上の POP3 例の同名プロパティを置換し、受信後処理や対応づけはそのまま維持する。
IMAP 平文なら `protocol: imap`・`port: 143` とし、認証方式も IMAP 用に明示する。

```json
{
  "sourceId": "support-pop3",
  "protocol": "pop3",
  "host": "pop.internal.example.invalid",
  "port": 110,
  "tls": "None",
  "authentication": {
    "mode": "password",
    "allowedMechanisms": ["USER/PASS"],
    "allowInsecurePasswordAuthentication": true,
    "userEnvironmentVariable": "MAILINGEST_LEGACY_USER",
    "passwordEnvironmentVariable": "MAILINGEST_LEGACY_PASSWORD"
  }
}
```

信頼できるネットワーク内だけで利用する。起動・設定検査時と各接続試行の認証前に、
認証情報・本文が平文で流れる危険を警告し、パスワード等の秘密はログに出さない。
公開ホスト名・公開 IP・判定不能の場合に警告を強める案は未決で、接続禁止の必須条件にはしない。

`certificateValidation` は省略時 `{ "mode": "Strict", "sha256Fingerprint": null }`。
TLS 利用時はチェーン・ホスト名・有効期間等を厳格に検証する。
自己署名証明書は信頼アンカーの登録を優先し、次の例外案はソース単位の明示と警告を必須とする。

| `mode` | 案と検査条件 |
| --- | --- |
| `Strict` | OS 標準の検証。フィンガープリント指定は禁止 |
| `AllowUntrusted` | 未信頼アンカーのチェーンエラーだけ緩和。名前不一致・期限切れ等は拒否。ピン指定は禁止 |
| `Pinned` | SHA-256 ピン一致時だけ未信頼チェーンを例外化。名前・期限等の検査は維持 |

`Pinned` の `sha256Fingerprint` は証明書 DER 全体の SHA-256、区切りなし 64 桁の 16 進数案。
別経路で確認し、大文字小文字を正規化して照合する。省略・不正形式・不一致は拒否し、
通常のチェーン検証や別モードへフォールバックしない。ピンの自動取得・初回信頼は行わない。
例外対象のチェーン状態・更新時のピン切替はレビューで確定する。
`None` では証明書設定を省略または既定に限り、例外モード・ピン指定は起動エラー。

環境変数の名前だけを JSON に記録する。
例えば `MAILINGEST_SUPPORT_PASSWORD_FILE` を指定すれば、そのファイルから解決する。
`MAILINGEST_SUPPORT_PASSWORD` と同時には指定できない。
ApiKey・ユーザー名にも同じ `_FILE` 規則を適用する。
既存 CLI の `PLEASANTER_*` から新しい `MAILINGEST_*` への移行は、第 2 段階で
互換エイリアスの有無を決め、既存 `check` を黙って変えない。

## 2. 正規化する項目

| 項目 | 意味・欠落時 |
| --- | --- |
| `subject` | MIME デコード済み単一行件名。空文字は欠落扱いで既定値を適用可能 |
| `bodyText` | 選択した本文を Unicode と安全な表示テキストへ変換したもの |
| `from.addresses` / `to.addresses` / `cc.addresses` | 解析済みアドレスの配列。表示名とは分ける |
| `from.names` / `to.names` / `cc.names` | 表示名の配列。未設定要素も取り扱いを明示する |
| `messageId` | 検証・正規化後の Message-ID。予約キーの計算とは別に任意保存 |
| `sentAt` | Date ヘッダの時差付き日時。欠落・不正なら未設定。処理時刻へ黙って置換しない |
| `receivedAt` | IMAP INTERNALDATE。POP3 は信頼できるサーバ受信日時を得られないため未設定 |
| `fetchedAt` | 取得時刻 UTC。受信日と同一視しない。業務ハッシュからは除外する |
| `attachmentCount` / `attachmentNames` | バイナリを含まないメタデータ。名前は安全化・上限検査後 |

複数差出人・宛先を黙って先頭 1 件にしない。`join` は配列にだけ許可し、必須とする。
Bcc は保存元で通常失われており、存在・完全性を保証しない。初期項目に含めない。
任意ヘッダ・Received の文字列解析は初期範囲外。
差出人や Message-ID は自己申告であり、本人確認・業務権限の根拠にしない。

## 3. 対応づけの評価規則（推奨）

テンプレート式・スクリプト・任意関数は **初期実装に含めない**。
宣言した項目参照、配列の連結、既定値、固定値、列の型変換に限定する。
複雑な加工が必要なら、後続で許可演算と計算量上限を設計してから導入する。

1. 未知の入力項目、同じ出力列の複数指定、固定値との衝突、予約列への指定は起動時エラー
2. 宣言したソース値を取り出し、欠落または空なら `default` を適用する。
   `default` と `fixedValues` は別物。固定値は入力に関係なく設定値を使う
3. 値が無く既定も無ければ列自体を送らない。更新時も既存値を消さない
4. 配列の `join`、本文の表示リテラル化、出力型変換、サイト側の長さ・選択肢を検証する
5. 1 列でも変換できなければ、そのメール全体を失敗にする。成功した列だけ部分送信しない

空文字による明示的な列クリアと日付クリアは初期範囲外。
Q の日付クリア用 sentinel を未検証で持ち込まない。
長すぎる件名・差出人・本文を切り捨てず、明示エラーにする。
「件名なし」のような既定値にも出力型・長さ制限を適用する。

| 出力列 | API 上の形 | 型規則 |
| --- | --- | --- |
| `Title` / `Body` | 直下のプロパティ | 文字列。Body は選択済み安全テキスト |
| `Status` / `Owner` / `Manager` | 直下のプロパティ | 整数・サイト許可値。最初は固定値のみ推奨 |
| `ClassA` 等 | `ClassHash` | 単一文字列。予約キー列は自由入力・検索可能な専用列 |
| `DescriptionA` 等 | `DescriptionHash` | 文字列。複数アドレスや本文の別保存先 |
| `DateA` 等 | `DateHash` | DateTimeOffset 入力から接続設定の timeZone へ変換 |
| `NumA` / `CheckA` 等 | `NumHash` / `CheckHash` | invariant の数値 / true・false。変換不能は失敗 |
| `AttachmentsA` 等 | `AttachmentsHash` | 初期は設定禁止。添付名の文字列を添付扱いしない |

日時 API の文字列表現とサーバ側の変換は実機未確認。
UTC の内部値を保持し、サイト・API 利用者のタイムゾーンを検証してから JSON 書式を固定する。
OS 間のタイムゾーン ID 対応も試験する。未設定日を現在時刻で補わない。
Owner / Manager 等をメールアドレスからユーザー ID へ自動解決する機能は含めない。

起動時に GetSite でサイトと列・長さ・選択肢・予約列を確認し、
設定だけで有効だと決めつけない。権限のため検証不能なら停止する。
本ツールはサイト設定を自動変更しない。
第 2 段階の推奨対象は記録テーブル。期限付きテーブル用の固有項目は別途確認する。

## 4. 組立結果の形

次は **API ペイロードの形を示す秘密抜きの断片**。認証を省略した実行例ではない。
実送信時に ApiKey と数値の ApiVersion を追加する。

```json
{
  "Title": "問い合わせ",
  "Body": "テキスト化し表示記法を無害化した本文",
  "Status": 100,
  "ClassHash": {
    "ClassA": "sender@example.invalid",
    "ClassB": "メール",
    "ClassZ": "<64文字の外部キー>",
    "ClassY": "<64文字の投射ハッシュ>"
  },
  "DescriptionHash": {
    "DescriptionA": "recipient@example.invalid"
  }
}
```

日時は [参照資料](設計の参照資料.md) のソース事実と実機未確認を分けるため、この断片には含めない。
予約列は利用者の対応づけから独立して必ず追加する。
`projectionHashColumn` に送信対象列の投射ハッシュを保存し、
メール内容自体の内容ハッシュは DB にだけ保持する。両者を混同しない。
`ApiKey` / `ApiVersion` / SiteId / Id / 権限プロパティをメール入力で上書きできない構造にする。
サイトごとの外部キー列は同一にし、同一サイトへ異なる予約列定義を与えた場合は起動時に拒否する。

## 5. 更新の意味

`onExisting: skip` を初期推奨とする。
既存メールと同じ Message-ID で内容も同じなら再作成しない。
`mappingRevision` を上げただけでサーバ上の全メールを勝手に更新しない。
明示再処理モードは第 2 段階で実装候補とし、対象 sourceId と外部キーの指定を必須にする。

`updateMapped` を選ぶ案では、明示再処理時に限り、設定された列だけを更新する。
未対応列と欠落値は維持する。予約キーは変更しない。投射ハッシュを比較して不要な Update を避ける。
手動編集を検出したら既定は競合保留とし、「ツール所有列は常に上書き」案はレビューで別途選択する。
複数の異なるメールを 1 案件へ結び付ける条件式や件名ベースの Upsert は設けない。
