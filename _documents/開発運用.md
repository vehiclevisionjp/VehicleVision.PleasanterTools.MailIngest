# 開発運用

## ブランチと PR

- `develop` が開発の本流、`master` がリリース確定用
- 作業ブランチは `develop` から分岐し、PR の base も `develop`
- Issue を作ってから変更し、PR 本文に `Closes #N` を書く
- 作業中は Draft とし、タイトルに `WIP:` を付ける。Draft 解除はレビュー可能、`WIP:` 除去はマージ可能の合図

## 定期実行

| 対象 | 頻度 | 仕組み |
| --- | --- | --- |
| npm・NuGet の更新 | なし（人が必要なときにまとめて行う） | 自動更新は 2026-11-16 に廃止した。脆弱性は下の `dependency-audit.yml` が検知する（下記「npm・NuGet の更新」） |
| Actions の更新 | 毎週 | Dependabot（`.github/dependabot.yml`）が `develop` 向けに PR を作る |
| 依存の脆弱性検査 | 毎週月曜と push | `dependency-audit.yml` |
| CodeQL と依存レビュー | 毎週日曜と push／PR | `codeql.yml`、`dependency-review.yml`。public か GHAS 有効のリポジトリだけで動く（下記） |

Pleasanter 本体は AI の事実確認専用で CI は使わない。
読む前に `bash scripts/sync-reference.sh` で上流 `main` の先頭を取得し、Git では追跡しない。
日次更新・ポインタ更新 PR・参照更新用 bot の迂回権限は不要。
再現性は文書に残す完全な SHA・ソースへの固定リンク・参照日で保つ。
過去の確認記録は自動で更新せず、再確認した場合だけ新しい根拠を記録する。
共有先の指定と取得失敗時の扱いは [参照ソース](../_reference/README.md) を参照。
既存の日次更新ブランチ・Draft PR・Issue の整理は別作業とし、この移行では触らない。

## GitHub の初期設定

新しいリポジトリを作った直後に行う。

1. 既定ブランチを `develop` にする
2. **リポジトリの設定を、全リポジトリと同じにする。** 定義と反映スクリプトの正本は Template だけにある（Template の `_documents/開発運用.md` を参照）。このリポジトリへは複写せず、管理者が Template の作業ツリーから `-Repository owner/name` を付けて反映する。
   マージ後にブランチを削除する・自動マージを許可する・ブランチ更新のボタンを出す。マージ方式は squash と merge commit だけ（rebase は使わない）。
   Wiki・Projects・Discussions は使わない（内容は `_documents` に置く）。依存グラフと Dependabot アラートも有効にする
   （無いと依存レビュー `dependency-review` が失敗する）。**public** のリポジトリでは、
   Dependabot のセキュリティ更新は**使わない**（npm・NuGet の更新は人が行う。下記「npm・NuGet の更新」）。
   シークレットスキャンとプッシュ保護は Template の定義に従い有効にする。
   internal / private では GitHub Advanced Security が要るため対象外
3. **ルールセットを設定する。** 定義（`develop-protection`・`master-protection`・`release-tag-protection` の 3 つ）と反映スクリプトの正本は Template だけにある（Template の `_documents/開発運用.md` を参照）。このリポジトリへは複写せず、管理者が Template の作業ツリーから `-Repository owner/name` を付けて反映する（管理者権限が要る）。
   必須チェックの既定と `-ExtraChecks` の指定も Template の文書に従う。**必須にしないと、失敗してもマージできてしまう**。
   このリポジトリは public で CodeQL を動かすので、`Analyze (csharp)` も必須チェックに含める（反映時に `-IncludeCodeQL` を付ける）。`cla` は公開範囲と前提ファイルから自動判定されるので、個別に指定しない。
4. リリースなどの自動化には GitHub App を使う。
   変数 `MY_REPO_AUTOMATION_BOT_CLIENT_ID` とシークレット `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY` を使い、
   各 workflow に必要な権限を確認する。参照取得には使わない
5. 公開範囲に応じて CodeQL と依存レビューを切り替える。**public** のリポジトリは何もしなくてよい。**internal / private** は、コードスキャンと依存レビューに GitHub Advanced Security（GHAS）が要る。GHAS を有効にしたら、リポジトリ変数 `CODEQL_ENABLED` を `true` にする（`gh variable set CODEQL_ENABLED --body true`）。有効にしない間、この 2 つのジョブはスキップされ、リリースの確認もスキップを許容する
6. ラベルを作る。定義は `.github/labels.json`、反映は `./scripts/Sync-Labels.ps1`（gh CLI でログイン済みであること）。
   参照ソース更新用のラベルの追加・削除は、この移行では行わない
7. 「Template repository」にするのはテンプレート側のみ。派生したリポジトリでは外す

## 外部記憶

Claude や Codex が作業の知見を残す必要があるときは、個別のリポジトリを作らず、Internal リポジトリ `VehicleVision.PleasanterTools.ClaudeMemory` に `MailIngest/` フォルダを作って管理する（運用は同リポジトリの README.md）。本体リポジトリへ記憶ファイルを置かない。

- 作ったら `CLAUDE.md` に URL を書く
- 作業ツリーはエージェントのメモリディレクトリそのものにし、別の clone を作らない（2 つあると片方が古くなる）
- 正式な規約の置き場所ではない。`.github/copilot-instructions.md` が常に優先され、食い違ったら記憶側を直す

## npm・NuGet の更新

- **自動更新は行わない**（2026-11-16 に patch 自動更新と、それに続く自動リリースを廃止した）。npm・NuGet の依存は、人が必要なときにまとめて更新する。
- 更新するときは、版・ロックファイル・NOTICE を 1 つの PR に揃える。
- 脆弱性の検知は残る。`dependency-audit.yml` が毎週月曜と push で検査し、`dependency-review.yml` が PR の依存の差分を見る。失敗したら人が気づいて更新する。
- GitHub Actions の版だけは Dependabot（`.github/dependabot.yml`）が `develop` 向けに PR を作る。
- リリースは `release-run.yml` を人が起動する（[リリース手順](リリース手順.md)）。
